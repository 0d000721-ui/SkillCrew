# SkillCrew 0.2 设计与实施记录

## 目标

延续用户已确认的下一版方向：自动修复、断点续跑、模型与 Skill 调度。保留新建 React 待办模板、冻结接口、真实文件归属检查和实际机器验收。

## 设计

- 每轮生成使用不可变输入快照。每个 worker 独立保存已通过文件门禁的检查点，绑定输入、接口、完整模型路由。单个失败不丢弃另一方成功结果。
- 集成先在候选目录完成，记录事务后替换输出；恢复时检查候选、原输出和备份的哈希，遇到用户改动停止。保留历史交付、验收和审查。
- 自动流程：规划 → 冻结 → 并行交付 → 机器验收 → 独立审查 → 主模型定位问题 → 按文件归属定向修复。默认最多两轮修复，接口变更、环境问题和越权操作阻塞；修复后重新执行全部验收及新会话审查。
- 模型目录同时记录候选、能力偏好、可用性来源和可选榜单证据。可用性优先；显式覆盖优先；有日期、来源的角色评分可参与排序，不伪造榜单分数。使用本机 agy models 与 Codex 模型缓存发现候选，Codex 缓存不代表后端承诺。
- Skill 是有角色与阶段范围的指令快照；自定义文件由用户显式登记。内容及哈希进入冻结计划。提示中按阶段和角色注入，不执行 Skill 附带脚本，不扩大写文件权限。
- `build` 一条命令完成全流程；`resume` 继续原运行。进度写 stderr，最终 JSON 写 stdout；`status` / `report` 展示修复与复用情况。

## 重点验证

中断发生在一方完成之后；集成事务中断；检查点、接口或输出被修改；机器失败不能被模型的空审查覆盖；修复轮数在重启后不能重置。
